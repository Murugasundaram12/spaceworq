# SPACEWORQ – Phase 2 Pending Business & Deployment Decisions

All architectural fixes requiring deterministic security/locking behavior have been implemented. The items below remain **Requires Business Decision** or require environment provisioning and must NOT be guessed or hardcoded prior to stakeholder approval.

| # | Domain / Code Reference | Status | Current Conservative Backend Behavior | Decision / Action Required Before Production |
|---|---|---|---|---|
| **1** | **Late Payment Capture on Expired Hold (`PaymentService::attemptConfirmPayment`)** | **Requires Business Decision** | When a payment webhook `payment.captured` arrives after `hold_expires_at` has passed (or capacity is exhausted), the backend refuses to confirm the booking, sets `Booking::STATUS_CANCELLED` + `InventoryReservation::STATUS_EXPIRED` + `PaymentTransaction::STATUS_FAILED`, preserves `gateway_payment_id` and records `failure_reason`, and marks `WebhookEvent` `FAILED` without triggering automated gateway refunds. | Decide operational policy for gateway-captured funds on expired holds: auto-refund via Razorpay API vs support manual refund queue vs auto-extend only when capacity remains. |
| **2** | **Partial vs Full Refunds & Gateway Refund API (`AdminOperationsController::recordRefund`, `PaymentGatewayInterface`)** | **Requires Business Decision** | `recordRefund()` accepts admin manual refund logs (`0.01 .. total_amount`), sets `PAYMENT_REFUNDED` even on partial amounts, does not execute live gateway refunds, and does not auto-release booking inventory if not already cancelled. | Define partial vs full refund ledger rules (`PARTIALLY_REFUNDED` vs `REFUNDED`), fee deductions, inventory release behavior, and approve Razorpay Refund API integration. |
| **3** | **Booking Policy Parameters (`system_settings` / `config/spaceworq.php`)** | **Requires Business Decision** | `default_tax_rate=null` (`0%` fallback), `booking_hold_minutes=null`, `half_day_multiplier=null`, `max_instant_booking_seats=null`, `cancellation_cutoff_hours=null` (`0.00` refundable), `pay_at_venue_enabled=false`, `allow_non_day_pass_instant_book=false`. | Approve explicit numeric values and boolean flags via Admin Settings or `.env`. Also schedule cleanup command once `booking_hold_minutes` is enabled. |
| **4** | **Razorpay Live/Sandbox Credentials (`config/spaceworq.php`)** | **Requires Business Decision** | `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, and `RAZORPAY_WEBHOOK_SECRET` unset -> payment endpoints fail closed with HTTP `503`. | Provision credentials in secure deployment secrets (never committed to repo). |
| **5** | **Approved CORS Origins (`config/cors.php`)** | **Requires Business Decision** | Defaults restrictively via `SPACEWORQ_CORS_ALLOWED_ORIGINS` (`http://localhost,http://127.0.0.1,http://localhost:8000,http://127.0.0.1:8000`). | Set exact production public website and vendor portal origin URLs in `SPACEWORQ_CORS_ALLOWED_ORIGINS`. |
| **6** | **Sanctum Token Lifetime (`config/sanctum.php`)** | **Requires Business Decision / Low** | `expiration => null` (tokens valid until explicit logout or password reset). | Confirm desired token TTL (e.g., `60 * 24` minutes or refresh rotation policy). |
| **7** | **Frontend API Integration (`spaceworq-clone/` & Vendor Files)** | **Requires Separate Approval** | Both design reference folders remain 100% unmodified (`56/56` SHA-256 baseline verified). | Explicitly authorize frontend binding work as a subsequent phase before adding `fetch()` / auth token calls into HTML/JS. |
